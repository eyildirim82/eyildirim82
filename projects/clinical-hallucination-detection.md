# Clinical Hallucination Detection for LLM-Generated Medical QA

An academic research project focused on detecting unsupported or fabricated clinical facts in answers generated by large language models over clinical narratives.

> The implementation repository is private. This page documents the architecture and engineering approach without exposing research data or private project code.

## Problem

A generated medical answer can be fluent while still introducing details that are not supported by the source narrative: an incorrect medication dose, fabricated date, wrong laterality, unsupported diagnosis or incorrect causal relationship.

Flat entity or triplet matching is often too coarse for these cases because a single clinical statement can contain several independently verifiable details.

## Approach

The project represents clinical information as an event-oriented property graph. The source narrative is converted into structured nodes, attributes and relationships so that generated answers can later be compared against the source at the level of individual clinical facts.

The current extraction pipeline uses MedGemma and separates the task into focused stages rather than asking one LLM call to perform entity extraction, normalization, classification and attribute generation at once.

```text
Clinical narrative
      |
      v
Entity spotting
      |
      v
Alias resolution / deduplication
      |
      v
Entity typing + stable IDs
      |
      v
Qualifier extraction
      |
      v
Clinical-scale recognition
      |
      v
Attribute population
      |
      v
Structured node registry
```

## Phase 1 — Entity Extraction

The first phase builds the node registry used by later graph construction and hallucination evaluation.

Key steps include:

- section-based narrative chunking
- clinical entity extraction
- cross-section alias resolution and deduplication
- entity classification and stable ID assignment
- qualifier extraction for properties such as laterality, severity and certainty
- recognition of clinical scales such as NIHSS, GCS and APGAR
- structured attribute population from the source narrative
- resumable per-chunk caching for long-running LLM extraction jobs

## Graph Model

The project currently models several categories of nodes, including:

- Patient
- Admission
- Condition
- Clinical Event
- Observation

Clinical entities receive stable opaque IDs so identity is separated from their surface form. Qualifiers are represented as structured data instead of being embedded only in entity names, which makes it possible to detect errors such as fabricated laterality or severity independently from the underlying clinical concept.

## Planned Evaluation Layers

Later phases are designed to compare the answer graph with the source graph across multiple levels:

- exact value checks for dates, doses and measurements
- exact detail checks for laterality and reaction type
- structural relation checks such as treatment or causality
- temporal direction checks
- certainty escalation checks, for example when a suspected condition is incorrectly presented as confirmed

## Engineering Notes

The pipeline is intentionally split into composable stages because entity spotting, classification, normalization and attribute extraction place different demands on the model.

Stateful operations work primarily on structured JSON, while narrative-dependent operations process section-level chunks. This keeps context sizes manageable and makes the pipeline easier to debug, resume and evaluate.

The implementation supports two local inference paths:

- MedGemma 27B served with vLLM
- MedGemma 4B served locally through Ollama

LLM calls use deterministic generation, bounded concurrency, retries with exponential backoff and per-stage caching.
